# 命题逻辑证明检查器

一个 React + Node.js 的命题逻辑自然演绎验算工具。前端负责编辑前提、结论和证明步骤；后端独立解析公式、检查引用与作用域，并通过真值表判断语义蕴含。

## 支持的公式

- 命题变量：以字母开头，后接字母或数字，例如 `P`、`Q1`。
- 非：`!A`
- 合取：`A & B`
- 析取：`A | B`
- 蕴含：`A -> B`
- 括号：`(A -> B) -> C`

优先级从高到低为：

```text
! > & > | > ->
```

蕴含按右结合解析。同一组前提、结论、证明步骤中至多允许 8 个不同变量。

## 证明规则

每一步包含：

- `id`：步骤编号；
- `formula`：该步得到的公式；
- `rule`：规则；
- `refs`：引用的早期步骤；
- `label`：假设标签。

支持：

- `premise`：重述前提；
- `assumption`：开设带标签的假设；
- `and_intro`：合取引入，引用两个步骤；
- `and_elim`：合取消去，引用一个合取式；
- `impl_elim`：蕴含消去，第一个引用是 `A -> B`，第二个是 `A`，得到 `B`；
- `impl_intro`：蕴含引入，关闭指定假设并引用该假设作用域内的一个结论，得到 `A -> B`；
- `or_elim`：析取消去，引用三个步骤：析取式 `A | B`、左支证明 `A -> C`、右支证明 `B -> C`，得到 `C`。可在 `branches` 中按顺序给出两支假设标签。

引用必须是当前作用域可见的早期步骤。关闭假设时必须先关闭内层假设；假设关闭后，其中间结论不能再被外层引用。

析取消去的两支蕴含式**必须**分别由「开设假设、在该假设作用域内推导、再用蕴含引入关闭该假设」得到：仅仅作为前提（或经其他途径）出现的 `A -> C`、`B -> C` 不能充当两支子证明（错误码 `OR_ELIM_REQUIRES_CLOSED_BRANCH`）。两支必须是不同标签、分别与析取式左右析取支一致、且在当前作用域关闭；`branches` 若填写，必须与引用实际关闭的标签一致。析取消去只解除两支分支假设：在外层假设仍开启时得到的结论仍属于该外层作用域，外层关闭后再引用会报 `SCOPE_VIOLATION`——因此嵌套使用析取消去（外层假设内做 ∨E，再关闭外层并引用其结论）是允许的，而跨作用域泄漏不允许。

后端按步骤顺序验算，并返回第一处错误；不会使用前端页面状态代替验算。若证明本身错误但结论仍为重言式，只返回证明错误，不伪造语义反例。若最终结论不被前提蕴含，则独立真值表模块穷举所有变量赋值并返回真实反例。

## 运行

```bash
npm install
npm test
npm run build
npm start
```

生产服务默认监听 `http://localhost:3001`。

开发模式可分别运行：

```bash
npm run server
npm run dev
```

Vite 会把 `/api` 代理到 Node 后端的 `3001` 端口。

## API

### `POST /api/verify`

验算完整证明。

```json
{
  "premises": ["P", "P -> Q"],
  "conclusion": "P & Q",
  "steps": [
    { "id": "1", "formula": "P", "rule": "premise", "refs": [], "label": "" },
    { "id": "2", "formula": "P -> Q", "rule": "premise", "refs": [], "label": "" },
    { "id": "3", "formula": "Q", "rule": "impl_elim", "refs": ["2", "1"], "label": "" },
    { "id": "4", "formula": "P & Q", "rule": "and_intro", "refs": ["1", "3"], "label": "" }
  ]
}
```

成功时返回逐步推导依据；失败时返回第一处错误码与中文说明。

### `POST /api/entailment`

只检查语义蕴含：

```json
{ "premises": ["P -> Q"], "conclusion": "Q" }
```

若不蕴含，返回所有使前提为真、结论为假的赋值。

## 测试覆盖

- 公式解析与运算符优先级；
- 合取消去、蕴含消去的错误使用；
- 假设开关、嵌套作用域和已关闭假设泄漏；
- 析取消去必须由两个已关闭的假设分支构成，普通蕴含前提不得冒充两支；
- 外层假设开启时的析取消去结论不得在该外层关闭后继续引用，而合法的嵌套析取消去应被接受；
- 最多 8 个变量限制；
- 非蕴含结论的穷举反例；
- 重言式结论不因证明错误而产生伪造反例；
- React 页面编辑后旧结果的归属标记，以及再次提交后的新结果归属；
- 真实 HTTP API 验算。
